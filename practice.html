02 / Git checkpoints

The save, stage, commit, and push workflow

For each checkpoint: edit, save, and check the rendered page. Then run the commands below, using a message that matches your actual change.

git status
git add practice.html
git commit -m "Add a third learning goal"
git push

Save frequently; commit at meaningful checkpoints. For this assignment, stage(by adding), commit, and push each completed checkpoint. Do not commit every keystroke or combine all five checkpoints into one final commit. In other projects, one commit can include several related files. Pushing updates the remote repository and is not required after every save.

Stop on an error. If pulling or pushing fails, read the message and ask for help. Do not force-push or delete work to bypass the error.

References: git add, recording changes, git pull, and git push.

Commit-message language and length

Use professional, specific language. Begin with an imperative verb: Add, Fix, Update, Remove, or Clarify. Describe the change, not the fact that you worked.

Aim for a subject of about 50 characters or fewer, including spaces. This is a readability target, not a Git-enforced limit. For this assignment, capitalize the first word and omit a final period. Avoid vague messages such as stuff, changes, done, or fixed it.

One subject line is usually enough here. When an explanation is useful, add a blank line and a short body explaining why; wrap body lines at about 72 characters.

Clarify the staging explanation

Explain that edits made after git add need to be staged again.

Reference: Pro Git: commit guidelines. Capitalization and punctuation are the suggested class style.

03 / Core HTML tag guide

HTML describes content and structure; CSS controls presentation. Expand a group to see common elements and examples. This is a beginner-focused selection, not every element in the HTML standard. Tables, forms, and media are optional exploration for this Git assignment.

Start with tags, attributes, nesting, and comments

An element commonly includes an opening tag, content, and a closing tag. An attribute supplies information in the opening tag.

<p id="intro" class="note">Learn <strong>one thing</strong> at a time.</p>
<!-- This comment is visible in the source, not in the rendered page. -->

id identifies one element and must be unique in the document; class is a reusable label for styling or scripting. Attribute values are quoted in this template. Close nested elements in reverse order.

Void elements, including <meta>, <link>, <img>, <br>, <hr>, and <input>, do not have closing tags.

To display markup as text, escape characters: write &lt; for <, &gt; for >, and &amp; for &. Indent nested elements consistently; indentation alone does not create visible spacing in a normal paragraph.

Reference: HTML Standard: syntax.

Document setup: the outer structure
<!DOCTYPE html>
The document-type declaration selects standards-mode rendering; it is not an HTML element.
<html>
The root element enclosing the document. Set its lang attribute.
<head>
Metadata and resource information. This is different from the visible <header>.
<meta>
Metadata such as character encoding; this page also declares a mobile viewport.
<title>
The document title shown in the browser tab, not the visible page heading.
<body>
The document content, including headings, paragraphs, links, and other elements.
<style>
CSS rules embedded in the HTML document.
<link>
A relationship to another resource; rel="stylesheet" loads an external CSS file.
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>My page</title>
  </head>
  <body>
    <h1>My page</h1>
    <p>A complete, small HTML document.</p>
  </body>
</html>

Reference: HTML Standard: document and metadata.

Headings, semantic sections, and containers
<h1> / <h2> / <h3> / <h4> / <h5> / <h6>
Six heading levels, highest to lowest. For this page, use one main h1, then logical subheadings.
<header>
Introductory content for the page or a section.
<nav>
A major group of navigation links.
<main>
The primary page content. Use one visible main.
<section>
A themed section, usually with a heading.
<article>
A self-contained composition, such as a post or profile.
<aside>
Related but secondary content, such as a supporting note.
<footer>
Footer information for the page or a section.
<address>
Contact information for the relevant page or article author; not a general-purpose address formatter.
<div>
A generic container for flow content when no more meaningful element fits.
<span>
A generic container within text, without adding meaning by itself.

Choose headings by their position in the outline, not their default size. Use CSS for appearance. A semantic element explains a role; a generic div or span does not.

Reference: HTML Standard: sections.

Paragraphs, emphasis, and small text
<p>
A paragraph. Start a new paragraph with another p element.
<strong>
Strong importance, seriousness, or urgency; not merely a request for bold text.
<em>
Stress emphasis; not merely a request for italics.
<b> / <i>
b draws attention without added importance; i marks an alternate voice or term. Use CSS for purely visual styling.
<mark>
Text highlighted because it is relevant in the current context.
<small>
Side comments or small print, not a general tool for shrinking text.
<sub> / <sup>
Subscript and superscript, such as a chemical formula or exponent.
<br>
A meaningful line break, such as a line in an address or poem. Not a spacing tool.
<hr>
A thematic break between topics; not just a decorative line.

Quotations, code, abbreviations, dates, and edits
<blockquote> / <q>
A longer quotation and a short inline quotation, respectively.
<cite>
The title of a work being referenced, not the name of its author.
<pre> / <code>
pre preserves whitespace; code marks computer code. Combine them for code blocks.
<kbd> / <samp> / <var>
User input, example program output, and a variable, respectively.
<abbr>
An abbreviation. Expand unfamiliar abbreviations in visible text, not only in a tooltip.
<time>
A date or time; datetime can provide a machine-readable value.
<del> / <ins>
Deleted and inserted document text. These elements do not create Git commits.

Lists: unordered, ordered, and descriptive
<ul>
An unordered list when item order is not significant.
<ol>
An ordered list for steps or rankings.
<li>
One item inside a ul or ol.
<dl>
A description list that groups terms with explanations.
<dt> / <dd>
A term and its description inside a dl. This tag guide uses them.
<ol>
  <li>Save the file.</li>
  <li>Stage the change.</li>
  <li>Commit the checkpoint.</li>
</ol>

<dl>
  <dt>Repository</dt>
  <dd>A project with version history.</dd>
</dl>

Put a nested list inside the relevant parent li, not beside it.

Reference: HTML Standard: grouping content.

Links, images, and captions
<a>
A hyperlink when it has href. Use link text that explains the destination.
<img>
An image: src locates it, and alt supplies a text alternative.
<figure> / <figcaption>
Self-contained content and its optional caption. A caption does not automatically replace image alt text.
<a href="#practice">Return to the practice area</a>
<a href="about.html">About this project</a>
<img src="workspace.jpg" alt="A laptop and notebook on a desk">

The first link works now. The other examples require files you create. Relative paths are resolved from the current document's location. When adding an image file, stage it along with the HTML that uses it.

Describe an informative image's meaning in its context. Use alt="" for a purely decorative image. Avoid vague text such as alt="image".

Accessibility reference: W3C: choosing image alternatives.

Forms: labeled controls and buttons
<form>
Groups controls for data entry. action is the submission destination; method is the submission method.
<fieldset> / <legend>
A group of related controls and its title.
<label>
A control label. Match for to the control's unique id.
<input>
A control whose type selects text, email, checkbox, or another input kind.
<textarea>
A multiline text field; it needs a closing tag.
<select> / <option>
A selection control and its choices.
<button>
A button. Specify type="submit" to submit or type="button" for a non-submitting action.

Expandable content: interaction without JavaScript
<details>
A disclosure widget whose contents can be expanded or collapsed. Add open to start expanded.
<summary>
The visible label that toggles its parent details; put it first inside that element.
<details>
  <summary>Show an example</summary>
  <p>This text appears when the reader expands the widget.</p>
</details>

This guide uses details and summary for every expandable group. Use the keyboard to focus a summary, then press Enter or Space.

Reference: HTML Standard: interactive elements.

Optional next steps: media and scripts
<audio> / <video>
Audio and video players. Add controls for playback controls.
<source>
An alternative media resource inside audio, video, or picture.
<track>
Timed text such as video captions; it refers to a separate text-track file.
<picture>
Image-source choices plus a required fallback img.
<iframe>
An embedded document. Give it a descriptive title and embed only trusted content.
<script>
Embedded or linked executable code or data, commonly JavaScript. Not needed for this lab.
<noscript>
Fallback content when scripting is unavailable or disabled, depending on context.

Media examples need real media files and appropriate alternatives, such as captions or transcripts. They are not required for this Git exercise. Do not add nonexistent file paths just to use more tags.

04 / Extend the page

Choose one extension. Make the new file and the HTML change that uses it part of the same commit so the checkpoint is complete.

Choice A: create and link about.html

Create about.html beside practice.html. Use the small document skeleton in the tag guide, give it an appropriate title, and add a heading and one paragraph about what you learned.

Add this list item inside the navigation list near the top of practice.html, then check that the link works:

<li><a href="about.html">About this project</a></li>

Add a return link inside about.html:

<a href="practice.html">Return to the practice page</a>

Save both files, then stage and review them together:

git add practice.html about.html
git diff --staged
git commit -m "Add and link an about page"

Synchronize and push using the workflow above.

Choice B: create and link styles.css

Create styles.css beside practice.html. For example:

/* This file contains CSS rules, not HTML tags. */
#practice {
  border-left: 0.4rem solid teal;
}

Uncomment the prepared link element after the style block in this document's head:

<link rel="stylesheet" href="styles.css">

Save both files, check the visible change, and stage them together:

git add practice.html styles.css
git diff --staged
git commit -m "Add external stylesheet"

Synchronize and push using the workflow above.

05 / Keep learning

This guide covers commonly used elements, not the complete language. Each reference group links to supporting documentation. For a full lookup, use the MDN HTML elements reference or the HTML Living Standard.

Before committing, check that your page still loads, headings remain logical, links point to real destinations, images have suitable alternatives, and only the intended changes are staged. Keep instructional comments when they are useful.

Keep the purpose in view: a clear Git history and useful commit messages matter more here than a complicated web page.
